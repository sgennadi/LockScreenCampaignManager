# Client Feedback / Live Dashboard — инструкция

Версия: **0.4.0-preview.2**. Функция предназначена для Windows 11 Enterprise/Education в домене Active Directory. Клиентам не требуются RSAT, WinRM, .NET или отдельная служба.

## Главное

В программе можно включить передачу **маленького диагностического JSON** от каждого компьютера. Данные публикуются независимо от того, открыт ли Manager. Когда Manager открыт, раздел **AD / GPO Deploy → GPO Operations → Client Health / Live** перечитывает отчёты каждые 15 секунд.

Отдельного сервера приложения, SQL и входящих соединений к компьютеру администратора нет. **Нужна одна выделенная файловая SMB-шара** с корректными ACL. Не используй SYSVOL, NETLOGON или административные `C$`/`ADMIN$` для отчётов: SYSVOL реплицируется между DC и не предназначен для телеметрии.

## Папка отчётов

Пример: `\\fileserver\LockScreenReports$`.

Менеджер создаёт папку определённой кампании:

`\\fileserver\LockScreenReports$\<CampaignID>\`

Агенты отправляют `PC001.json`, `PC002.json` и т. д. В каждый файл включаются только:

- `schemaVersion`, `campaignId`, `computerName`, `timestampUtc`;
- `stage`: `Pending` / `Active` / `Completed` / `Error`;
- `health`: `Healthy` / `RepairNeeded` / `Error` / `Completed`;
- `expectedImage` — **только имя JPG**, не полный путь;
- `imageMatches`, `registryMatches`, `taskPresent`;
- количество пропавших/испорченных JPG и версия агента.

Пароли, BitLocker/LAPS-ключи, имена пользователей, полные пути реестра, лог-файлы и снимки экрана **не отправляются**. Отчёт — самодиагностика агента, а не независимое криптографическое доказательство того, что картинка видна на экране.

## Настройка безопасности SMB

1. Создай отдельную SMB-шару на обычном файловом сервере, не на контроллере домена.
2. До развёртывания нажми в Manager **Обратная связь → Подготовить папку кампании**.
3. Для администратора назначь чтение, а компьютерам целевой области — минимальные права создания отчёта. Избегай общего `Everyone Full Control`.
4. Рекомендуемая схема NTFS: Domain Computers — разрешение просмотра папки/создания файлов **в пределах папки кампании**; `CREATOR OWNER` — изменение созданных им файлов; администраторам — чтение и управление. Отдельно проверь права уровня SMB. Учитывай, что для замены/удаления временных файлов нужны права владельца на созданный файл.
5. Для нескольких доменов лучше использовать отдельные шары или строгую изоляцию папок. Не предоставляй Domain Computers права изменять отчёты других ПК. Проект сам ACL **не меняет**.
6. Проверь запись от реальной учётной записи **компьютера** (`DOMAIN\PC$` под LocalSystem), а чтение — от учётной записи администратора, которой открывается Manager.

Без папки/прав отчёты недоступны, но **сама кампания продолжает работать**: сетевую ошибку агент регистрирует локально.

## Порядок включения

1. В главном окне выбери картинки, даты и нажми **Обратная связь**.
2. Отметь включение, укажи корневую UNC-шару и интервал: **5–60 минут** (по умолчанию 15).
3. Создай папку кампании и настрой ACL.
4. Экспортируй пакет / разверни через **AD / GPO Deploy** на тестовой OU.
5. Клиент при установке, смене изображения и раз в 15 минут отправит JSON.
6. В разделе **Client Health / Live** нажми **Загрузить компьютеры из AD**, чтобы получить точное количество целей (пересечение OU и группы компьютеров). Затем **Обновить**.

## Как читать статусы

- **Работает**: актуальный отчёт, все JPG целые, локальный task существует, реестр соответствует текущему JPG. Это не подтверждает, что экран блокировки сейчас открыт.
- **Готов / ожидание**: агент установлен, файлы и task проверены, дата начала ещё не наступила.
- **Требует проверки**: пропавшие JPG, неправильный реестр, task или самодиагностика агента.
- **Устарело / офлайн**: нет нового отчёта примерно три интервала (минимум 45 минут). Не утверждает точно, что ПК выключен — SMB или сеть могли быть недоступны.
- **Нет отчёта**: компьютер входит в OU/группу, но от него ещё не приходили пригодные данные.
- **Завершено**: агент сообщил об окончании и восстановлении при завершении.

При выключенном Manager отчёты сохраняются. При запуске снова доступно последнее состояние. Для аудита есть **Экспорт CSV UTF-8**.

## Ограничения

- Manager обновляет таблицу каждые 15 секунд, **но ПК отправляют отчёты с указанным интервалом**; это не мгновенное подтверждение в реальном времени.
- Требуются DNS, SMB TCP 445 и права компьютеров в шаре.
- Данные компьютера самодекларируемые; не используй счётчик как независимый аудит безопасности/сертификат соответствия.
- ACL файлового сервера должны защищать отчёты от подмены другой машиной. В программу не встраиваются учётные данные домена/токены GitHub.
- Если целевой список AD не загружен, менеджер видит только отправивших отчёты, **но не может подсчитать общее количество целевых ПК**.
- Сначала проверь полный цикл на 1–3 Windows 11 клиентах: установка, ожидание, показ картинки, самовосстановление, окончание, доступность SMB и повторное использование GPO.


## Новые возможности версии 0.4.0-preview.2

В разделе Client Health появились **Repair Selected**, **Уведомления**, **Сохранить снимок**, **Итоговый отчёт**, **История**. Выбор компьютеров для Repair повторно проверяется по AD, затем подтверждается GUID GPO. Уведомления выключены по умолчанию и не отправляют команды ПК автоматически. История и отчёты сохраняются в LocalAppData администратора, а не в SMB. Подробности: [Client Management](CLIENT-MANAGEMENT-RU.md).
