# Device & Repair Dashboard — руководство

Версия менеджера: **0.4.0-preview.8**, без повышения.
Этот раздел встроен в существующий переносной .NET 10 EXE и не требует RSAT,
WinRM, второго EXE, сервиса, скрипта-установщика или дополнительной DLL.

## Назначение

Открой **GPO Operations → Device & Repair Dashboard**. Выбери
управляемую GPO в **GPO: Disable / Reuse / Delete**, убедись, что
в **Client Health / Live** настроена выделенная SMB share, и нажми
**Load verified AD devices**. Программа заново проверит компьютеры
в пересечении выбранных OU и Security Group, не используя отчёты
клиентов для определения прав на доступ. Неоднозначные короткие
имена компьютеров отклоняются.

**Refresh reports** собирает:
- последние SMB Client Health JSON для выбранной кампании;
- пользовательскую очередь Deferred Repair;
- защищённую машинную очередь gMSA (в том числе при Disabled);
- ранее сохранённые локальные Snapshot/Final того же домена, OU,
  группы и Campaign ID. История общих событий не приписывается
  отдельному компьютеру без индивидуального подтверждения.

Данные берутся только из этих источников, без внедрения нового
клиентского агента или RPC. Автообновление отключено по умолчанию;
по отдельному выбору обновление каждые 60 секунд работает только
при открытой вкладке.

## Значение колонок

- **Client Health / Stage**: данные из файлов, которые отправил агент.
- **Expected image**: ожидаемое имя JPG, переданное агентом. Это
  **не доказательство** реального отображения на экране пользователя.
- **Last report**: дата последнего принятого отчёта агента.
- **Integrity**: оценка из сообщений агента о локальных файлах,
  реестре и задаче Task Scheduler; независимой аттестации нет.
- **Agent**: версия клиентского агента, не версия изображения.
- **Repair queue**: состояние уже подтверждённых запросов в
  пользовательской или gMSA очереди.
- **History**: только архивы, явно сохранённые ранее в профиле
  администратора, а не выдуманный непрерывный журнал изменений.

Отсутствие отчёта означает **Unknown / No report**, а не сбой
компьютера. «Healthy» и «Completed» — утверждения клиента,
а не подтверждение фотографии локскрина.

## Repair Selected

Выдели 1–25 компьютеров, нажми **Repair selected** и подтверди
переход в существующий проверенный процесс Repair.
Панель сама не создаёт удалённые задания. Перед RPC менеджер снова
проверит список AD, текущую GPO и обе очереди. Дальше необходимо
прочитать Preview и ввести **полный GUID GPO**.

Если в защищённой очереди gMSA есть неопределённый RPC
(\`Attempting\`, \`AwaitingTask\`, \`AwaitingHealth\`),
новый запуск блокируется даже после отключения gMSA.
При Disabled также блокируются \`Queued\`: нельзя запускать
параллельную ручную задачу, пока прежняя ждёт возврата сети.
Повторное включение gMSA не обновляет прежние разрешения
или 14-дневные сроки. Для ручного решения сначала проверь
**gMSA 24/7**, **Client Health** и запущенные задачи на клиенте.

## Безопасность и ограничения

Нельзя делать вывод «обои показаны пользователю» только из SMB.
Несколько локальных архивов показывают исторические *снимки*
состояния, но не независимое подтверждение экрана.
UniversalDiagnostics остаётся очищаемой локальной ручной очередью,
UniversalUpdater — ручной проверкой/подготовкой пакетов.
Реальные доменные проверки и gMSA/RPC во время перезагрузки
ещё должны пройти приёмку на test OU с клиентами Windows 11.

## Тестирование

Windows x86 и x64 CI проверяет архитектуру, сборку EXE,
встроенные тесты прав AD scope, проверку объединения данных,
разделение «No report» и «Healthy», запрет повторного RPC,
а также безопасную работу уже существующих функций.
