# UniversalUpdater для LockScreen Campaign Manager

**Версия модуля:** 0.1.0-rc.1, внедрён исходниками в один EXE .NET 10.
**Версия менеджера:** 0.4.0-preview.9 (новый preview-билд).

## Интерфейс

Кнопка **Updates** в главном окне открывает английский DPI-aware диалог.
**Check for updates** проверяет закреплённый GitHub Releases источник
sgennadi/LockScreenCampaignManager (только новые версии SemVer,
каналы Preview + stable и Stable only). При наличии релиза показывает
changelog. **Download & verify** по отдельному согласию сохраняет ZIP
в локальный staging; контролирует имя, SHA-256, размер архива,
безопасность ZIP и архитектуру PE. Никакая установка не выполняется.

Репозиторий приватный. По желанию администратор может вставить
**fine-grained GitHub token** только с разрешением **Contents: Read**
на этот конкретный репозиторий в поле **Private GitHub token**.
Токен остаётся только в оперативной памяти открытого окна,
не сохраняется в настройках/логах/реестре, очищается при закрытии
и передаётся исключительно на закреплённые `api.github.com` URLs.
GitHub отдаёт приватный asset через numeric asset ID; при редиректе
на `release-assets.githubusercontent.com` Bearer-токен не передаётся.
Не используйте токен с правами записи.

HTTP 404 рассматривается как ошибка доступа к релизам, а не как
доказательство, что новых версий нет. **Open releases** по-прежнему
открывает страницу в браузере. Реальную проверку нового preview
на приватном GitHub Release требуется выполнить отдельно.

После скачивания проверяются SHA-256, ZIP, PE architecture и
**Windows Authenticode** через WinVerifyTrust. При отсутствии/ошибке
подписи менеджер сообщает **NOT VERIFIED**. Даже успешная
проверка WinVerifyTrust не означает совпадение с закреплённым
сертификатом издателя. **Автоматическая установка запрещена.**

**Backup status** — только безопасный просмотр состояния локального
файла `.bak` рядом с текущим EXE, включая архитектуру и SHA-256.
Менеджер не пытается заменить собственный EXE во время работы и не
управляет защитной копией gMSA как частью автоматической установки.
Восстановление — только отдельно утверждённая операция на остановленном
host с проверкой цифровой подписи и последующим self-test.

## Формат GitHub Release

После создания нового релиза с SemVer-тегом (например, v0.4.0-preview.10)
прикрепляйте к нему assets с точными именами:

- LockScreenCampaignManager-Update-win-x64.zip
- LockScreenCampaignManager-Update-win-x86.zip

В каждом ZIP должен быть **только один** файл в корне:
LockScreenCampaignManager.exe. Иные файлы, каталоги и ссылки запрещены.
GitHub Release должен предоставлять SHA-256 digest. Workflow
Build portable EXE собирает эти ZIP и проверяет состав, но лишь
выкладывает их в GitHub Actions artifacts. Публикация Release — отдельный
административный шаг. SHA-256 НЕ эквивалент независимой подписи издателя;
automatic install запрещена без доверенной Authenticode-валидации
и отдельного проверенного установщика.

## Обновление сервера с gMSA

1. Получите новую сборку из доверенного источника и проверьте её.
2. На управляющем Windows-сервере используйте Configure gMSA → Disable;
   очередь сохраняется, уже отправленные клиентские задания не отменяются.
3. Закройте GUI и вручную обновите его бинарный файл по принятой
   корпоративной процедуре. Не заменяйте защищённый EXE в ProgramData
   пока работает gMSA.
4. Запустите новый EXE с правами администратора, откройте
   Configure gMSA → Install / Repair. Это обновит защищённую копию
   и Task Scheduler, без повторного подтверждения старой очереди.
5. Выполните Check и Run gMSA test, проверьте heartbeat и Client Health
   для тестового компьютера. Убедитесь, что Attempting после аварии
   превращается в AwaitingTask без повторной регистрации RPC.

Реальные проверки AD/gMSA, частных GitHub Releases и смены Lock Screen
остаются отдельной приёмкой на рабочем сервере; CI их не заменяет.
