# LockScreen Campaign Manager — руководство администратора

## Назначение
Windows-приложение для временных кампаний экрана блокировки на доменных ПК.
Оно не привязано к конкретному домену: можно автоматически найти текущий
Active Directory или указать DNS-домен и доступный контроллер домена вручную.

**EXE автономный** (win-x64 / win-x86, .NET 10 self-contained).
Для GUI не нужен установленный .NET Runtime. Для удалённого развёртывания
требуются Windows PowerShell 5.1, LDAP/ADSI, SMB/SYSVOL и Windows gpedit.dll COM;
модули RSAT и WinRM не требуются. У администратора должны быть права создавать
и привязывать GPO, изменять её ACL и записывать файлы в SYSVOL.

## 1. Подготовка кампании

1. Запусти \`LockScreenCampaignManager.exe\`.
2. Введи название (например, Campus Safety Week).
3. Выбери дату начала и время смены (например, 09.11.2027, 14:00).
4. Выбери Windows-часовой пояс целевых компьютеров (например,
   \`Israel Standard Time\`). Приложение проверяет переходы летнего времени.
5. Добавь от 1 до 30 изображений JPG/PNG/BMP и расположи в нужном порядке.
6. Изображение №1 показывается с начала кампании, №2 — через сутки,
   и так далее. Каждый слайд меняется в **одно и то же локальное время**.
7. \`Последний слайд, часов\` определяет, сколько часов показывать
   последнюю картинку (по умолчанию 24). После этого наступает очистка.
8. Нажми \`Проверить\`, затем \`Сохранить проект\` или \`Экспорт для GPO\`.

**Выгрузка** создаёт папку с \`campaign.json\`, копиями картинок
\`images/01.jpg\`, \`images/02.jpg\` и т.д., их SHA-256, PowerShell-агентом
\`LockScreen-Agent.ps1\` и руководством для GPO.
Повторный экспорт с тем же идентификатором не перезаписывает готовый пакет.

## 2. Выбор домена и развёртывание

1. Нажми \`AD / GPO Deploy\`.
2. Укажи DNS-домен или оставь поле пустым для автоопределения.
3. Выбери контроллер домена; для записи нужен **writable DC**.
4. Подключись через \`Current Windows account\` либо
   \`Other domain account\` (пароль остаётся только в текущей сессии).
5. Нажми \`Connect / Refresh\`, найди OU и группу безопасности.
6. **Важно:** для Computer Startup в группе должны состоять учётные
   записи **компьютеров**, а не только пользователей. OU также определяет
   область действия GPO. Пользователи внутри OU не являются целью Startup.
7. Введи имя **новой** GPO и нажми \`Preview (no changes)\`.
   Просмотр только читает данные; не создаёт GPO и не копирует файлы.
8. Проверь OU, группу, домен/DC, пути и размер пакета.
9. Нажми \`Create GPO + copy to DC\` и явно подтверди.
   Программа создаёт новый объект GPO, загружает файлы, прописывает
   PowerShell Startup, меняет Security Filtering и связывает GPO с OU.

Не заменяй существующую GPO без отдельного процесса изменения: приложение
специально блокирует совпадения имён. LDAP и SYSVOL реплицируются не мгновенно.
После развёртывания дождись репликации и проверь результат в GPMC/на тестовом ПК.
При частичном сбое сохраняется информация для ручного разбора, а не
предпринимается опасное удаление чужих GPO.

## 3. Что происходит на целевом компьютере

\`Computer Configuration > Policies > Windows Settings > Scripts >
Startup > PowerShell Scripts\` вызывает агент с \`-Mode Install\`
в контексте LocalSystem при **загрузке ПК**.

Агент:
- Проверяет издание Windows (Enterprise/Education), манифест и SHA-256 картинок.
- Копирует пакет в \`C:\ProgramData\LockScreenCampaigns\<campaign-id>\`.
- Запоминает исходные значения \`LockScreenImage\` и
  \`NoChangingLockScreen\`, не перезаписывая первую резервную копию.
- Создаёт локальное задание Task Scheduler (SYSTEM): ежедневные точки смены
  картинок, контроль при загрузке и завершение кампании.
- В нужный момент выставляет оба проверенных параметра реестра.
- При пропущенном включении ПК выбирает актуальную картинку по календарю,
  а не начинает с первого дня.
- После завершения восстанавливает предыдущие параметры и удаляет локальные
  картинки, скрипт и задание.

**Почему нужен локальный планировщик:** Startup GPO не запускается точно
в 14:00; он выполняется при старте Windows. Локальное задание отвечает
за точное расписание даже без повторных входов пользователя.

Компьютер, который был выключен весь период кампании, при позднем запуске
не должен заново запускать изображения. Доменная GPO и исходники в SYSVOL
не удаляются агентом: их удаляет администратор после проверки завершения.

## 4. Тестирование без запуска кампании

Открой локальный установленный агент с \`-Mode Status\` либо
\`-Mode Test -TestImage 2 -TestSeconds 180\`. Тест временно применит выбранную
картинку и должен восстановить исходное состояние по истечении времени.
Проверяй работу на Windows 11 Enterprise/Education на тестовой OU,
не изменяя время и дату продуктивных компьютеров.

## 5. Настройки UI и DPI

- \`Настройки\` — плотность Auto / Compact / Comfortable.
- Масштаб GUI: 100, 110, 125 или 150%.
- Масштаб шрифта: 90, 100, 110 или 125%.
- DPI Windows определяется автоматически (PerMonitorV2); интерфейс
  поддерживает системные масштабы, не требует вручную считать DPI.
- Основное окно запоминает размер, расположение и максимизацию.
- Настройки пользователя лежат в
  \`%LOCALAPPDATA%\LockScreenCampaignManager\ui-settings.json\`.

## 6. Диагностика / поддержка

Если возникает ошибка, открывается окно с **обезличенными данными**.
Доступны только осознанные действия:
- Скопировать диагностическую сводку.
- Сохранить локально в \`UniversalDiagnostics\` со статусом \`pending\`.
- Открыть GitHub Issues (в приватном репозитории). Передача данных
  произойдёт только после твоей проверки и ручной отправки.

Кнопка \`Диагностика\` открывает список уже сохранённых сообщений.
Никаких паролей, учётных данных AD или токенов GitHub в EXE не хранится.
Без подтверждения приложение ничего никуда не отправляет.

## 7. Что ещё нужно проверить перед продакшеном

Успешный GitHub Actions Build доказывает компиляцию, базовую проверку PowerShell
и self-test расписания/очереди. Он **не** заменяет интеграционную проверку
создания GPO, Security Filtering, Win11 Lock Screen, офлайн-клиентов,
DST и удаления локальных файлов. Развёртывать сначала на небольшой тестовой OU.
